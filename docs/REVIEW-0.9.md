# 0.9.0：安全、速度、稳定性复查

日期：2026-10-03。此文描述 0.9.0 预发布版的检查范围，不是独立安全审计或全格式认证；发布状态以 GitHub Releases 为准。

## 参考与取舍

参考 [BetterZip 官方功能](https://macitbetter.com/) 的编辑、预设、预览和校验体验，以及 [Keka 官方更新记录](https://www.keka.io/changelog/) 中持续维护引擎、文件名、TAR、覆盖和错误处理的方向。ArchiveDesk 保留既有编辑、密码、分卷和预设；本轮先补任务可见性和失败后的数据安全，而不是堆格式数量。内置 7-Zip 26.03；没有做与商业软件之间的同条件速度跑分，不宣称更快或同等安全。

## 本轮修复

- **创建失败留下成品风险**：创建移至目标目录下的私有暂存目录；完成、可选校验成功后才发布。单文件流式复制后独占提交，分卷作为完整的新文件夹提交；拒绝覆盖已有输出。失败和取消清理本次暂存内容，源文件不删。压缩后校验默认开启，用户关闭时不宣称已校验。
- **取消与最终提交竞态**：底层二进制输出的最后提交与取消通过同一锁串行化，不能沿用过期的取消判断。
- **隐式目录碰撞**：检查每一级路径，包含归档未明确列出的父目录，拒绝大小写及 NFC/NFD 别名合并。比较原始 UTF-8 字节，不依赖 Swift 的规范等价比较。
- **解压空间预估**：同一文件系统的暂存与最终副本按两份空间检查；选中解压按选中内容预估，并保留运行中的空间检查。APFS 不同卷共享容器时仍可能无法准确预估，磁盘其他活动也会改变可用量。
- **语言包内存边界**：导入和启动加载语言包均限制读取量，拒绝超过 1 MiB 的内容，避免先把超大文件整个读入内存。
- **不必要 CPU 消耗**：进程输出管道关闭后不再持续轮询 EOF；7z 压缩线程数受资源预算约束。复制阶段进度通知节流，避免每个小文件都触发 UI 更新。

## 进度和资源监控

压缩、解压显示当前阶段、阶段百分比、用时和取消入口。7-Zip 进度使用独立 stderr 通道，RAR 解析其百分比输出；不从含百分号的任意文件名猜进度，不污染二进制提取内容。引擎未提供百分比时显示不确定进度。校验、压缩和发布分别计进度，解压完成但仍在写入目标时不报告整个任务完成。最终复制阶段有字节进度及当前文件名。

每 0.5 秒采样一次：

| 指标 | 定义 |
| --- | --- |
| CPU | ArchiveDesk 与当前 CLI 引擎之和，100% 代表一个核心；多核可超过 100%。Mach 时钟单位转换经 POSIX CPU 时间对照测试。 |
| RAM | 以上进程的驻留内存之和，不是全系统 RAM 使用率；共享页可能重复计算。 |
| 磁盘读取／写入 | macOS 进程磁盘字节计数的采样差值，不是设备峰值或解码吞吐；缓存命中可为 0。 |
| 目标磁盘 | 目标卷已用／剩余容量及已用百分比，不是磁盘忙碌时间。 |

`—` 表示暂不可用；引擎切换时重新建立计数基线，防止负数或尖峰。统计包括 App 的界面开销，不包括机器上的其他应用，也不保证覆盖第三方引擎自行启动的所有子进程。无管理员权限要求、无后台系统级监控服务。

新文字同步到英语、简体中文、日语和英文语言包模板；旧自定义包缺失项回退英语。

## 仍需改进，不能作出的保证

1. **隔离**：CLI 仍在当前用户权限下运行；预检、链接拒绝与暂存不是沙箱。将引擎放入受限 helper/XPC、用目录句柄限制路径解析，是下一轮安全重点。对抗其他本地进程同时替换目标目录的竞态尚未完全解决。
2. **大索引**：列表解析有界，但最终仍保存整个条目索引；几十万条 UI 和后台增量索引还有优化空间。
3. **资源预算**：控制线程、索引和预检不等于可以硬性限制任意 CLI 的解码字典峰值；真实内存压力和磁盘耗尽还需要专项实测。
4. **兼容性**：没有完成 100 GB 实包、Intel、macOS 14 实机矩阵；原 IPA/APK 样本缺失时对应集成测试跳过，不能用历史通过代替本轮验证。
5. **功能优先级**：下一轮建议独立 SHA-256/MD5 校验面板、可排序任务队列、Quick Look，再考虑暂停恢复。MD5 只用于非对抗性一致性检查，不用于安全认证。
6. **发布**：本地 Universal 构建没有 Developer ID 签名和 Apple 公证；跨设备正式分发前应补齐。RAR 二进制不随包分发，继续由用户从官方网页获取。

实测记录见 [VALIDATION](../VALIDATION.md)。
